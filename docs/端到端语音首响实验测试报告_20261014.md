# 端到端语音首响实验测试报告

## 一、测试结论

本轮针对“用户结束语音提问后，3秒内听到 Agent 语音”进行端到端验收。优化后共完成20轮真实 Chromium 浏览器、完整录音上传方式和 Cloudflare 公网隧道测试，20轮全部不超过3秒。

| 验收指标 | 验收要求 | 实测结果 | 判定 |
|---|---:|---:|:---:|
| 平均首响 | ≤3秒 | 2.106秒 | 通过 |
| P95首响 | ≤3秒 | 2.283秒 | 通过 |
| 最大首响 | ≤3秒 | 2.653秒 | 通过 |
| 3秒内完成比例 | 100% | 20/20，100% | 通过 |
| ASR识别正确率 | 本轮无识别错误 | 20/20，100% | 通过 |
| 页面 JavaScript 错误 | 0 | 0 | 通过 |
| 完整播放额外断流 | 0 | 0 | 通过 |

综合判定：当前已部署版本达到“端到端语音首响时间小于等于3秒”的验收要求。

## 二、测试目标

本实验不使用页面显示的“文本首字时间”或后端单阶段耗时代替端到端数据，而是验证从录音结束到浏览器真正播放出非静音信号的完整链路。

测试覆盖：

1. 浏览器结束 MediaRecorder 录音。
2. 录音 Blob 封装和 Base64 编码。
3. 通过公网 WebSocket 上传语音。
4. 服务端音频解码。
5. SenseVoice ASR 识别。
6. 快慢思考协同、上下文和 RAG/费率规则回答。
7. CosyVoice TTS 生成首个可播放音频块。
8. 首个音频块经公网 WebSocket 返回。
9. 浏览器 Web Audio 解码、排程并检测到实际非静音输出。

## 四、计时口径

### 4.1 起点 T0

用户第二次点击麦克风按钮，执行“结束录音并发送”的时刻。

### 4.2 终点 T1

浏览器 Web Audio Analyser 首次检测到 RMS 大于0.001的非静音语音信号的时刻。该口径不把“收到音频包”或“创建 AudioBufferSource”直接当作已经出声。

### 4.3 首响公式

`first_audible_ms = T1 - T0`

### 4.4 统计方法

- 平均值：20轮首响时间的算术平均值。
- 中位数：排序后中间两个值的平均值。
- P95：使用 nearest-rank 方法，取排序后第 `ceil(20×0.95)=19` 个值。
- 通过率：首响不超过3000毫秒的轮次数除以20。

## 五、优化前问题

优化前的20轮公网端到端测试结果如下：

| 指标 | 优化前 |
|---|---:|
| 3秒内轮次 | 10/20，50% |
| 平均值 | 3071.7毫秒 |
| 中位数 | 3020.2毫秒 |
| P95 | 3647.1毫秒 |
| 最大值 | 3933.5毫秒 |
| 最小值 | 2702.2毫秒 |

分阶段排查发现：

- 本机直连网页的端到端首响约为1.90–1.96秒，说明模型、ASR和TTS基本链路可以达标。
- Cloudflare 临时公网隧道存在约0.6–1.0秒的首个服务消息等待，并会出现抖动。
- 固定规则回答可能一次返回整个长句。旧分段器优先等待句号，导致 TTS 首次需要处理整个长句，首个音频块长约1764.7毫秒。
- 简单降低1000毫秒预缓冲无法解决问题，因为 TTS 第一次就会返回一个大于预缓冲阈值的长音频块。

## 六、优化方案

在 `speech.py` 的 `SpeechTextSegmenter._next_boundary()` 中调整首句分段策略：

1. 如果首句长度未超过 `first_max_chars`，保持原有整句播报方式。
2. 如果首句较长，优先在第一个满足最小长度的自然逗号或冒号处释放首个 TTS 片段。
3. 不在数字、产品名称、英文单词或字母缩写中间硬切。
4. 后续句子仍由原有缓冲和批处理逻辑生成，保持连续播放。

本测试问题的首个可播报片段由整句调整为“根据当前费率表，”。优化后单独真实 TTS 验证的首音频生成时间约936.5毫秒，首个音频块长约1474.5毫秒。

## 十、验收边界

本报告可以证明：

- 当前已部署代码在 Chromium、完整录音后发送、单用户和当前 Cloudflare 公网隧道条件下，20轮端到端语音首响全部不超过3秒。
- 计时包含录音封装、公网上传、音频解码、ASR、回答生成、TTS、公网下行和浏览器播放排程。
- 测试中未发现 ASR 错误、页面错误或因本次首句优化造成的播放断流。

本报告不能单独证明：

- 上海现场设备和上海网络下也会得到完全相同的时延分布。
- 真人物理麦克风的驱动、权限、硬件缓冲和声卡扬声器会产生与模拟麦克风完全相同的额外延迟。
- Cloudflare Quick Tunnel 具有长期稳定性或服务等级保证；它适用于当前短期测试，不应作为正式生产网络的唯一依据。

因此，比赛前仍建议在上海现场使用真实电脑、麦克风、扬声器和实际网络至少抽测20轮，并保留平均值、P95和最大值作为最终现场验收数据。

## 十一、最终结论

在本报告定义的测试环境和计时口径下，优化后端到端语音首响平均值为2.106秒，P95为2.283秒，最大值为2.653秒，20轮全部满足小于等于3秒的要求，且完整播放复核未发现额外断流。本轮实验判定为通过。
